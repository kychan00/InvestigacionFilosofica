# Phase 6A — SIVA portrait evidence in shadow mode

The existing SIVA resolver retains the actual selected Wikidata P18 claim, entity ID, revision when available, Commons file name and bridge method. The separate portrait decision uses an asserted authority-image-link and can reach probable, not confirmed; a license, ORCID, or authorship decision cannot establish depicted identity. An exact canonical filename is required for this experimental assertion. No new external calls or changes to the ordinary image acceptance policy. Live evidence without a known revision is explicitly marked live-unversioned, not identified as the HF revision.

Opt-in authorityPreview=1 evaluates only after the existing image validation, download and decode complete. Missing or failed media remains unresolved; normal portrait lifecycle and limits remain unchanged. The session keeps the assessment transiently and clears it on exit, with no persistent storage. The existing default portrait presentation is unchanged. A probable label is experimental, not a guarantee about the person.

The subsequent phase must address independent ORCID-free candidate discovery, stronger documentary evidence and conflicts, and verify real named-author cases before activation. The legacy historical/name and bibliographic bridges remain hypotheses, not verified person identities. No merge to production.

New unit tests exercise scope, missing/conflicting metadata and existing request counts. The responsive portrait smoke now exercises the experimental assessment across 32 viewport/theme combinations and verifies cleanup. CI validation remains required.

## Phase 6B — independent routes (preview only)

The experimental resolver queries Wikidata's ORCID and OpenAlex claims independently (not the OpenAlex API). Either route may be absent; distinct or truncated identifier hits abstain. A unique OpenAlex statement plus a matching name can support a probable portrait even with an unverified ORCID; the ORCID-only route requires a verified registry flag and matching name. Contradictory recorded identifiers never authorize a replacement. When both identifier searches are empty, name search may retrieve candidates, but only exact local creator IDs and an authored DOI or two distinct authored works with Wikidata P50 corroboration support the bibliographic bridge. The existing public resolver is unchanged. The preview waits for bibliographic retrieval and ORCID checks to settle before opening a portrait session. Existing request timeout, media validation and transient cleanup are retained. The new route may add one identifier search and use the existing bounded name/works discovery calls; no commercial service or direct OpenAlex API. Tests use synthetic responses, not proof of real-world person identity. Real provider coverage and false-match evaluation remain phase 6C/7.

## Phase 6C — real-profile comparative audit

Run the new audit against the same checksum-verified author-index release used by the authority benchmark. Thirteen purposeful names cover modern, historical, Latin American and homonym cases. Retain the candidate list and evaluate at most three distinct profiles per name, with up to 100 indexed works each; the rest are reported, not merged or silently interpreted as negatives. No manually manufactured IDs or injected reference QIDs. Compare the legacy and experimental routes on the same snapshot profile after the public ORCID name check. Record real network outcomes, source identifiers, license, media size, request count, elapsed time, and V2 evidence. The audit uses a bounded two-worker pool and explicit timeouts, never calls OpenAlex API, and stores no portrait bytes. Browser CORS/decode remains a separate live provider smoke; the audit checks HTTP downloads, not visual identity. The JSON artifact includes review flags, gains/losses and coverage counts, not precision or recall. Historical reference QIDs are only comparisons, not gold labels; every profile still requires independent human review. No production activation. Results pending the CI run.

### Phase 6C — infrastructure repair

First live audit: 25 candidate profiles, 20 measured, 5 not sampled; 0 downloaded by either route. Wikidata returned HTTP 429 on 45 requests. The separate browser smoke failed before execution when an unrelated onnxruntime-node install timed out. Isolate Playwright in the runner temporary directory and leave production dependencies untouched. Serialize audit Wikimedia requests with 2.5-second spacing, respect Retry-After, and skip requests during cooldown rather than retrying aggressively. Successful JSON metadata is bounded and reused only in process for comparable paired observations; no media is cached or persisted. Record rate limiting separately from abstention. The new run is required before drawing coverage conclusions; a green technical check alone cannot close scientific validation.
